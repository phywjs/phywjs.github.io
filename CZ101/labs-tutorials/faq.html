Notes on Lab #1

Procedures, Functions, and Sub-programs

These terms can be used inter-changeably. Basically this is like a boss delegating some work to his workers. In programming, the 'boss' is usually the "main" program, and the 'workers' are the procedures or functions that are assigned some work.

Just as a boss will give input data to the worker in order for the worker to carry out the task (eg. calculate something), the main program must supply the function with data. We call this "arguments" or "parameters" Also the boss expects the worker to give him results, so in the same way, the function must return some data to the main program. (note: the main program is also said to "call" a function, and to the function, the main program is the "calling" function)

For example: The main program wants to calculate a sum of 2 integers, so we can write the program as the main function (note that the main "program" is also a function/procedure) calling a procedure called "sum", which takes 2 integer arguments (the numbers to be summed) and returns an integer (the result of the summation). in C: 

        int sum(int a, int b)      /* a function called "sum" 
                                      expecting 2 integers a & b to be 
                                      given by the calling program */
        {
          return (a+b);
        }

        main()
        {
          int c;
          c = sum(1,2);   /* here the main() calls the sum() function
                             and c will get the results of the sum() */
        }

For this lab, we will have a C program (the test programs given by Dr Wang) calling an assembly program (written by you). Arguments are passed to your assembly functions through registers $4, $5, and the C program expects the return results from the assembly function in register $2.

Compilation

You may compile both the C program and the assembly program together on the same line, e.g: 

  cc c_prog.c asm_prog.s -o run_me

Recall that the "-o" option specifies the executable file to produce. If you omit it, then the executable will be called "a.out".

Note: make sure your C program has the ".c" behind the name, and make sure the assembly program has the ".s" behind as well.

More Hints on Lab 1

Question 1

The question asks for an assembly program that copies a sequence of bytes from one location in memory to another location. The memory locations are GIVEN from the calling program (the callbcopy.c), by passing parameters in $4 and $5. At the very beginning, $4 contains the starting address of the source, and $5 contains the starting address of the destination. The sequence of bytes (array) is marked as terminated by a null byte (a byte with the value 0).

For illustration purpose, let us assume that $4 contains the number 100, and $5 contains 60. Here are what happen for the contents of memory and registers. 

Just before bcopy start:                        After executing bcopy:   

            address   content                       address   content

               ...    | ... |                        ...    | ... |    
               59     |     |                        59     |     |
     $5  ->    60     |     |                        60     | 65  |
               61     |     |                        61     | 66  | 
               62     |     |                        62     | 67  |
               63     |     |                        63     |  0  | 
               64     |     |                        64     | ... |
               ...    | ... |                        ...    | ... |

               99     | ... |                        99     | ... |
     $4  ->   100     | 65  |                       100     | 65  |
              101     | 66  |                       101     | 66  |
              102     | 67  |                       102     | 67  |
              103     |  0  |                       103     |  0  |
              104     | ... |                       104     | ... |
              ...     | ... |                       ...     | ... |

   $4 = 100, $5 = 60                        $2 = 3, $4 = ..., $5 = ...

In other words, the bytes at location 100, 101, 102, and 103 are copied to location 60, 61, 62, and 63, respectively. Unspecified entries may contain unpredictable values. Note that each byte has a unique address, consecutive bytes differ in addresses by 1. (Each word has 4 bytes, thus next word is 4 bytes away).

Before executing bcopy, $4 contains 100, and $5 contains 60, in the above example. We don't care about the values in $4 and $5 after execution of bcopy. but $2 should contain the number of bytes copied, not counting the last byte of value 0. So, the above example should have 3 in $2 as the return value of the function bcopy.

Note that if $4 contains 100, then 

   lb $3, 0($4)
makes $3 contain 65, the value at memory address 0 + $4 = 0 + 100 = 100. $3 does NOT contain the value 100. On the other hand 
   add $3, $0, $4
makes $3 contain the value 100, as in $4.

Question 2

This question asks you to find 'b' in a sequence of bytes. The character 'b' in memory is just a number, in this case the number 98. See the ASCII table for the correspondence between printing characters and internal presentation in computer.

Again, let us assume, for the seek of concreteness, that the memory and register contents look like these: 

Before program execution:              After execution:
      address   contents

       1001     | ... |                 MEMORY NO CHANGE
$4 ->  1002     | 105 |
       1003     | 109 |
       1004     |  98 |
       1005     | 105 |
       1006     |  98 |
       1007     | 101 |
       1008     |   0 |
       1009     | ... |

 $4 = 1002, $5 = ...                    $2 = 1004, $4 = ...,

This sequence of bytes representing the string "imbibe". $4 is the first and only argument for this function bfind. The value in $4 is set by the calling program (in this case, the C program callbfind.c). You should load a byte into a register from memory to see if it is a 'b' (i.e. 98) or value 0. You start from the address given in $4 ($4=1002 in the above example), if is not a 'b' or 0, look at the next byte, and so on until you find a 'b' or 0.

After the first 'b' or 0 is found, before returning to calling program, you should make sure that $2 contains the address of the byte you have just found. In the above example, $2 should contain 1004, which is the address of the first 'b' in "imbibe".
